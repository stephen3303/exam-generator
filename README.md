# Exam Generator

A Microsoft Access app that keeps an approved question bank and builds inspection exams from it: questions are written, checked by subject matter experts and approved; exams are drawn from templates, reviewed topic by topic and approved.

The front end is built in code with the [access-modern-ui](https://github.com/stephen3303/access-modern-ui) kit, so every form has the kit's look and palettes. It is a build output: edit the files in `access\`, never the built `.accdb`.

## What's here

```
access/build.ps1              builds the front end (access\build\ExamGenerator.accdb)
access/backend/               the shared data file's script (modBuildBackEnd.bas) and new-backend.ps1
review/                       review prompts and the review task for Stephen's review VMs
access/kit/                   the kit, copied unchanged (KIT_VERSION.txt says from which commit)
access/tools/                 the kit's build tools (palettes, line numbers, dialog watch)
access/src/modules/           the app's code: modBuild (BuildAll and every form), modGlobals, modUI,
                              modErrors (error handler and log), modBuildAppearance, modPalette
access/src/forms/             the app's form code-behind (frmMain, the shell)
access/src/themes/            the build palette (generated by tools\make_themes.py)
access/src/help/help.txt      the help topics (Help in the sidebar, or F1)
```

## Build and open

Requires Microsoft Access 2016 or later (Microsoft 365) on Windows.

```powershell
cd access
.\backend\new-backend.ps1                    # a new, empty data file at build\ExamGen_BE.accdb (never overwrites)
.\build.ps1 -BackEnd .\build\ExamGen_BE.accdb   # front end linked to that data file
.\build.ps1                                  # front end with no data linked, for UI work
.\build.ps1 -UiOnly                          # rebuild code and forms, keep the links
```

The data file holds the question bank, exams, each person's Exam Generator roles and switches (keyed on the shared Personnel file's `person_id`; names and accounts stay in the Personnel file), the editable help topics and the error log. `new-backend.ps1 -Path <file>` makes it somewhere else; `BuildBackEnd` in `modBuildBackEnd.bas` still works by hand from any Access database.

Then open `access\build\ExamGenerator.accdb`. The build stops and prints any Visual Basic or Access dialog it meets (a compile error, an error message) instead of hanging. The code loaded into the front end has line numbers so the error log names the failing line (`-NoLineNumbers` leaves them out).

The palettes are generated: after changing one, run `python tools\make_themes.py src` in `access\`.

## Build phases

The front end is built in the ten phases of the front-end plan. Pages a later phase fills in open as placeholders that name their phase, so the whole sidebar can be clicked through from phase 1.

| Phase | Adds |
|---|---|
| 1 | Repo, kit, shell with every page as a placeholder, palettes, help, error log |
| 2 | Sign-in from the shared Personnel file, roles, linking the shared data file |
| 3 | Help topics edited in the app (Admin: Help topics); the help is kept in the data file's `help_topic` table and read at start-up |
| 4 | Admin: topics with their SMEs, templates with their topics (`dlgTemplateTopic`), people and routing (roles and the DH, XO and SM steps), rules and lists (the overlap rule and the difficulty and classification lists). Built by `modBuildAdmin`; shared lookups in `modAdmin` |
| 5 | Question bank (search, status chips, column filters, references and the questions citing each) and the question editor (parts with points and portion markings, answer options, references, reference answer, history; versions and audit rows), with `dlgPart`, `dlgReference` and `dlgHistory`. Built by `modBuildQuestions`; the save and submit rules and the editor's working copy in `modQuestions` |
| 6 | Question approvals |
| 7 | Exam topic reviews |
| 8 | Exams and exam approvals |
| 9 | Dashboard, statistics, notifications |
| 10 | Admin: logs (the audit trail and the error log) |

## Updating the kit

Copy the kit's `kit\` folder and the tools listed above over `access\kit` and `access\tools`, record the new commit in `access\kit\KIT_VERSION.txt`, rebuild, and click through every page in a light palette (Navy) and a dark one (Midnight).
