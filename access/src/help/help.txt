Exam Generator help topics. The build loads this file into the front end (LoadHelpTopics);
rebuild the front end after editing it. Everything above the first topic is ignored.
From build phase 3 the topics live in the shared data file, where the admin edits them in
the app, and this file only seeds them the first time.

Format:
  === key | Title      starts a topic. A key with a dot (exams.new) is listed
                       indented under its parent. Page keys match frmMain's page keys.
  # Heading            a heading inside the topic
  - text               a bullet point
  **text**             bold
  Other lines are paragraph text; a blank line ends a paragraph.

These topics are stubs: each phase writes the full help for the pages it builds.

=== start | Getting started
The Exam Generator keeps an approved question bank and builds inspection exams from it. Each page in the sidebar is one part of that work.

# Signing in
Your Windows sign-in finds you in the shared Personnel file, so most days you don't sign in at all. The sidebar shows only the pages your Exam Generator roles use: **My reviews** for SMEs, **Approvals** for the Department Head, XO and Senior Member, and the **Admin** pages for the admin. If you have no role yet, the app says so and names the admin to ask.

# Getting help
Click **Help** in the sidebar, or press **F1**, to open help for the page you are on. Choose any other topic from the list on the left, or type in the search box to find the topics that mention a word. Press **Enter** in the search box to open the first match.

# Go anywhere with Ctrl+K
Press **Ctrl+K** and start typing the name of a page. Press **Enter** to go to the first match, or use the **Up** and **Down** arrows to choose another. **Esc** closes it.

# Other things in the sidebar
- **My settings** holds your colors (**Appearance**) and, later, your notification switches.
- The **arrow** at the top folds the sidebar to icons, to give the page more room. Click it again to open it. Point at an icon to see its name.

=== dash | Dashboard
Your open reviews, the approvals waiting for you, your returned questions and the topics short of questions. This page comes in build phase 9.

=== review | My reviews
Each exam topic you review: check the questions drawn for it, swap any out and sign off. This page comes in build phase 7.

=== approvals | Approvals
Questions and exams waiting for your approval, one queue for each approver. This page comes in build phases 6 and 8.

=== exams | Exams
Every exam and where it stands. The department head starts a new exam here. This page comes in build phase 8.

=== questions | Question bank
Every question in the bank, and the references they cite. Everyone can look; SMEs write and change questions.

# Finding a question
- Type in the **search box** to find questions by their words, their topic or their number (Q12).
- The **chips** show questions by status. **All** shows the current version of each question; **Retired** shows the versions a newer version replaced.
- The **funnel** on a column header shows only the rows with the values you tick. The chips' counts follow the search and the funnels.
- **Export** saves the rows shown as a CSV file or an Excel workbook.

# The question on the right
Pick a row to see the question: its status and who last acted on it, its text, topic, type, difficulty, points, portion marking, parts and references. **History** shows every version and who wrote, changed, submitted, approved or rejected it.

# Writing and changing questions (SMEs)
- **New question** opens the editor on a blank question.
- **Edit**, or a double-click on the row, opens the question. A draft or a rejected question can be changed; one in review, approved or retired opens read-only.
- To change an approved question, use **More** > **Edit as new version**. The new version goes through the whole approval again.
- **More** > **Delete draft** deletes a draft that was never submitted and is on no exam.

# Statuses
- **Draft**: being written. Only drafts and rejected questions can be changed.
- **In Review**: submitted, waiting on the DH, then the XO, then the senior member.
- **Approved**: can be drawn for exams.
- **Rejected**: sent back with the approver's comments (see History). Change it and submit it again.
- **Retired**: replaced by a newer version. It is kept for the record and never drawn.

# References
The **References** tab lists the documents questions cite, with how many current questions cite each. SMEs and the admin can:
- Correct a reference's title, number or revision and click **Save**. Every question citing it shows the change, so a different document should be a new reference instead.
- Click **New reference** to add one to the list.
- Use **More** to turn a reference off (it can't be cited again; questions citing it keep it), or to delete one that no question cites.
- Click **Show in the question list** to see only the questions citing it. **Show all questions** goes back to all of them.

=== questions.history | A question's history
Every version of one question, newest first: who wrote, changed, submitted, approved, rejected and retired it, when, at which approval step, and any comments. The rows are never changed or deleted.

Click **Copy** to put the history on the clipboard as text, to paste into an email or a report.

=== qedit | Question editor
Write a question with its parts, portion markings, answer options and references. Nothing reaches the bank until you click **Save**, so no one else sees a half-written question.

# The question's own fields
- **Topic**: type part of its name and pick it from the list.
- **Type**: multiple choice, true/false or short answer. Only multiple choice questions have answer options.
- **Difficulty** and **Points**. Points go in whole or half points, from 0.5 to 100.
- **Portion marking**: the question's classification marking. Once a question has parts, it is set from them: the highest part's marking.

# The tabs
- **Question**: the text as it will print. Extra spaces and blank lines are tidied when you save.
- **Parts**: a question with parts (A, B...) needs at least two. Each part has its own text, points, portion marking and reference answer, and the parts' points must add up to the question's. Parts are lettered by their order; the arrows move a part.
- **Answer options**: the choices of a multiple choice question, lettered A, B... in their order. With parts, each part has its own options: pick the part in the box beside the buttons before you click **Add option**. Select an option and click **Mark correct**; each question or part has one correct option.
- **References**: the documents the answer comes from, with the paragraph. **Cite a reference** picks one from the shared list or adds a new one.
- **Reference answer**: the answer key for the command. It is never printed on the exam.
- **History**: every version's audit rows.

# Saving and submitting
- **Save** (Ctrl+S) checks the question and keeps it as a draft. If something is missing, it says what and takes you to it.
- **Submit for approval** saves it, checks that it has references and, for multiple choice, at least two options with one correct in each group, then sends it to the department head. You can't change it while it is in review.
- If someone else saved the question while you had it open, Save says who and asks before saving over their changes.
- Leaving with unsaved changes asks whether to save them.

# Versions
An approved question is changed by starting a new version (**More** > **Edit as new version**). Saving the new version retires the approved one, so it can't be drawn for new exams until the new version is approved. Deleting the new version's draft before it is submitted puts the approved version back.

# More
- **Undo changes** drops your changes since the last save.
- **New question** starts a blank one.
- **Delete draft** deletes a draft that was never submitted and is on no exam.

=== qedit.part | A question's part
A part (A, B...) of a multipart question.
- **Label**: set by the part's place. Move the part to change it.
- **Points**: whole or half points. The line under the fields says what the question's points leave for this part.
- **Portion marking**: the part's own classification marking. The question takes the highest of its parts'.
- **Text**: the part as it will print.
- **Reference answer**: the part's answer key, never printed.

Click **OK** to keep the part in the question. It is saved to the bank with the question, when you click **Save** in the editor.

=== qedit.reference | Citing a reference
- **Cite one already listed**: type part of its title or number and pick it from the list. Only references turned on are listed.
- **Add a new reference**: give its title, number and revision as the document shows them. OK adds it to the shared list at once, so other SMEs can cite it too, even if you don't save the question.
- **Paragraph**: where in the reference the answer is, such as 3.2.1 or Table 4. It is optional.

To cite a different reference, remove the citation and cite the other one.

=== stats | Statistics
Questions given per topic and per reference over a period or exam series. This page comes in build phase 9.

=== topics | Admin: Topics
Topics are the subjects questions are written in. Each has a number of questions it starts with on a template, and the SMEs who review its questions and exams.

# The list
Each row shows the topic, its SMEs, how many **approved** questions it has, and its status:
- **Active**: in use, with enough approved questions.
- **Short**: in use, but with fewer approved questions than the overlap rule needs for the most questions any active template gives it. New exams may not be able to keep to the rule for it.
- **Off**: turned off. Templates can't add it.

Type in the search box to find topics by name or description. Click a column caption to sort by it.

# Adding and changing a topic
Click **New topic** (or press **Ctrl+N**) and type its name. It starts active, with the questions per topic set under **Rules and lists**. Change its name, **Questions per exam** or description on the right and click **Save** (or press **Ctrl+S**). The **Active** switch saves as soon as you flip it.

# SMEs
Type part of a name in the box under **SMEs**, pick the person and click **Add**. Anyone in the Personnel file can be picked: adding them gives them the SME role, and access to the Exam Generator, if they don't have it yet. Select an SME and click **Remove** (or right-click them) to take them off this topic; they keep the SME role.

# Questions on hand
The panel at the bottom compares the topic's approved questions with what the overlap rule needs. See **Rules and lists** for how that number is worked out.

# Turning off and deleting
Click **More** (or right-click the topic's row) to turn the topic off or on, or to delete it. A topic can be deleted only while no question, template or exam uses it; otherwise turn it off.

=== templates | Admin: Templates
A template is one kind of exam: the topics it covers, in the order the exam shows them, and how many questions each topic gives.

# Adding and changing a template
Click **New template** (or press **Ctrl+N**) and type its name. Change its name or description on the right and click **Save** (or press **Ctrl+S**). The **Active** switch saves as soon as you flip it; only active templates can be used for a new exam.

# Its topics
- **Add topic** opens a window to pick a topic and set how many questions it gives. The count starts at the topic's own questions per exam, and the window says whether the topic has the approved questions the overlap rule needs for that count.
- **Change** (or double-click a topic) sets the selected topic's count.
- The **arrows** move the selected topic up or down. Exams list their topics in this order.
- **Remove** takes the selected topic off the template. The topic itself stays, and exams already made keep it.

Right-click a topic for the same choices. The line above the topics adds up the topics and questions an exam from this template has.

# Copying and deleting
Click **More** (or right-click the template's row) to copy the template with its topics, or to delete it. A template can be deleted only while no exam has been made from it; otherwise turn it off.

=== people | Admin: People and routing
Who can use the Exam Generator, who holds each role, and so who each step of an exam's approval goes to.

# The approval route
The three cards across the top name who holds **Department head (DH)**, **Executive officer (XO)** and **Senior member (SM)**, the steps an exam goes through after its SMEs sign off. A step nobody holds says so: exams can't pass it until someone does.

# Adding a person
Type part of a name in the box, pick the person and click **Add person**. Only people in the shared Personnel file can be picked. Anyone missing has to be added there first: a Personnel admin can click **Personnel** to do it. Adding someone gives them access to the Exam Generator; give them a role on the right so they have something to open.

# Roles
Click a person in the list, then flip their switches on the right. Each switch saves as soon as you flip it.
- **Can use the Exam Generator**: off stops them signing in to this app.
- **Exam Generator admin**: the Admin pages.
- **Subject matter expert (SME)**: writes questions and reviews the topics they are an SME of (set on the **Topics** page).
- **Department head**, **Executive officer** and **Senior member**: approve questions and exams at their step.

Nobody can turn off their own access or their own admin, and the app always keeps one admin. Taking SME away from someone who is an SME of topics takes them off those topics too, once you agree.

=== rules | Admin: Rules and lists
The overlap rule that limits how far a new exam may repeat recent exams, and the lists questions choose their difficulty and classification from.

# The overlap rule
- **Most of a topic's questions that may repeat**: of the questions a topic gives an exam, at most this share may have been on any of the recent exams. 0% means all must be fresh.
- **Recent exams checked**: how many of the latest exams count as recent.
- **Questions per topic to start with**: what a new topic, and a topic added to a template, starts with.

Moving a slider lists the topics that would be short of approved questions under the new values, before anything is saved. Click **Save** (or press **Ctrl+S**) to use them, or **Undo changes** to go back. Use the **Left** and **Right** arrow keys on a slider to move it a step.

# How many questions a topic needs
If an exam takes n questions from a topic, at least n minus the repeats allowed must be fresh, and those stay recent for the next exams checked. So a topic needs at least (exams checked + 1) x (fresh questions an exam) approved questions to meet the rule exam after exam, using the most questions any active template gives it. For example, 4 questions an exam, 25% may repeat and 10 exams checked: 3 must be fresh, so it needs 11 x 3 = 33.

# Difficulty and classification levels
Click **Add** to add a level. Select a level and click **More**, or right-click it, to rename it, move it, or delete it.
- A difficulty level in use can't be deleted: **turn it off** instead. Questions that have it keep it; new ones can't pick it.
- Classification levels are listed lowest first. An exam's overall marking is the highest level of its questions, so keep the order right. A level in use can't be deleted, but its marking and portion mark can be changed.

=== helptopics | Admin: Help topics
Change the help for any page or dialog, with no new copy of the app. What you save shows at once here, and for everyone else the next time they open the Exam Generator.

# Changing a topic
Click a topic in the list, or type in the search box to find the topics that mention a word. Change its title or text, then click **Save** (or press **Ctrl+S**). **Preview** opens the help window on the topic as it will look. **Undo changes** puts back the saved text.

# Writing the text
- A line starting **#** and a space is a heading.
- A line starting **-** and a space is a bullet.
- Put two stars on each side of a word to make it bold.
- A blank line starts a new paragraph; other lines join into the paragraph above.

# Adding a topic
Click **New topic** (or press **Ctrl+N**). The key ties the topic to what it explains: a page's topic uses the page's key, such as **exams**, and F1 on that page opens it. A topic under another uses its key, a dot and a word, such as **exams.new**, and is listed under it. The key can't change once the topic is saved.

# Where the help comes from
Each new copy of the app brings its own wording for the topics, but only for topics the data file doesn't have yet. Once a topic is in the data file, your wording stays, even when a newer copy is installed.

=== settings | My settings
Click **Appearance** to choose the colors the whole app uses on this computer. Your notification switches come in build phase 9.

=== directory | Personnel
One shared Personnel file holds everyone who can use the Navy apps built on
this kit. Your Windows sign-in finds you in it, so most days you don't sign in
at all. Only Personnel admins can open this page.

# Find someone
- Type part of a name, rank, sign-in name or Windows account in the search box.
- **Can open** says whether they may open this app. **Status** is Admin, Active or Inactive.

# Add people
- **Add person** opens a blank form. It stays open after Save, so you can add the next person straight away.
- **Import** adds everyone in a CSV or Excel file. The first row names the columns: First name and Last name, and any of Middle initial, Rank, Command, Email, Sign-in name and Windows account.
- Imported people can open this app. Rows with no name, or a sign-in name or Windows account someone already has, are skipped and listed.

# Change someone
Double-click them, or pick them and choose **Edit**.

=== directory.person | Add or change a person
- **Windows account** is DOMAIN\user, such as NAVY\jsmith. With it saved, the person is signed in by Windows with no password.
- **Sign-in name** is what they type on the sign-in screen. Leave it blank and it is made from the Windows account, or from the first initial and last name.
- **Active** lets them sign in. Make people inactive rather than deleting them, so their past work still shows their name.
- **Personnel admin** lets them open the Personnel page. There is always at least one active admin, and you can't remove your own admin access.
- **Can open Exam Generator** controls this app only. Each app keeps its own list.

# Passwords
An app password is only needed on the sign-in screen, after Sign out or on a computer where their Windows account isn't saved.
- To reset a forgotten password, type a new one twice and Save, then tell them.
- Passwords need 8 or more characters, and capitals count.

=== directory.signin | Signing in
Exam Generator signs you in with your Windows account when it is saved in Personnel and has access to Exam Generator. This screen shows when it isn't, when it has no access to Exam Generator or is turned off, or after **Sign out**. It names the Personnel admins to ask.
- Type your sign-in name and app password, then **Sign in**.
- Tick **Use my Windows sign-in next time** to skip this screen on this account.
- No password yet? If this is your own Windows account, you can choose one now. Otherwise ask a Personnel admin to set one.
- **Copy** puts your Windows account on the clipboard, to send to an admin.

=== directory.setup | Setting up Personnel
Exam Generator needs the shared Personnel file and couldn't find it.
- **Find the Personnel file** when another app already uses Personnel. It is usually in a Personnel folder beside the app's data folder.
- **Create a new Personnel file** only for the first app set up here. You become its first admin and add the others.
- **I'm not the admin** shows a note to send your admin, with **Copy**, then closes Exam Generator.

# The site key
Creating the file fills in a new random **site key** that locks it. You can keep it or type your site's own (12 to 20 characters). It is saved as Personnel.key in the same folder, and every app reads it from there, so nobody has to type it again. Keep Personnel.key with the file: without it the file won't open.

# After everyone was deleted
When an admin deleted all data and ticked the Personnel box, the Personnel file is still there but has nobody in it. The next person to open an app sees **Create the first admin**: type your name, rank and app password, and you become the Personnel admin for every app. Then add the others again, or **Import** them. If you are not the admin, choose **I'm not the admin** instead. A backup copy of the old file and its key is in the Backups folder beside it.
